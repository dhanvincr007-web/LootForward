# LootForward — Gamers Helping Gamers

> **Verified-first gaming charity donation platform.** Connect gamers with community programs that need consoles, gadgets, and direct financial support — through an audit-driven workflow designed to reduce fraud.

---

## ✨ Features

| Feature | Details |
|---|---|
| 4-page client-side SPA | Hash-based routing — no page reloads |
| Interactive particle background | Three.js mouse-reactive particle field |
| Donation category switcher | Console · Gadget · Money with dynamic form panels |
| Recipient selection | Three verified community programs (demo data) |
| Client-side form validation | Field-level error highlighting + alert messages |
| Dynamic receipt generation | Unique `PENDING_AUDIT_*` ticket + FNV-style local hash |
| Firebase Firestore integration | Modular SDK v10+, gracefully disabled without config |
| Responsive dark UI | Bootstrap 5 · Glassmorphism · Orbitron + Inter fonts |
| Accessibility | `aria-*` labels, reduced-motion media query, semantic HTML5 |

## 🚀 Local Development

> **Important:** Do **not** open `index.html` directly via `file://`. ES Modules require an HTTP server.

### Option 1 — npm (recommended)

```bash
npm start
# Opens http://localhost:5500
```

### Option 2 — Node.js `serve`

```bash
npx serve . --listen 5500
# Opens http://localhost:5500
```

### Option 3 — Python HTTP server

```bash
python -m http.server 5500
# Opens http://localhost:5500
```

### Option 4 — VS Code Live Server

Install the **Live Server** extension, right-click `index.html` → **Open with Live Server**.

## 🔥 Firebase Setup

The application ships with **safe placeholder values** in `firebaseConfig` inside [`app.js`](app.js). Firestore integration is automatically disabled while placeholders are present — the app runs fully client-side without Firebase.

To enable cloud persistence:

1. Create a project at [console.firebase.google.com](https://console.firebase.google.com).
2. Add a **Web app** and copy the generated `firebaseConfig` object.
3. Replace the placeholder block in `app.js`:

```js
const firebaseConfig = {
  apiKey: "YOUR_FIREBASE_API_KEY",
  authDomain: "YOUR_FIREBASE_PROJECT.firebaseapp.com",
  projectId: "YOUR_FIREBASE_PROJECT_ID",
  storageBucket: "YOUR_FIREBASE_PROJECT.firebasestorage.app",
  messagingSenderId: "YOUR_FIREBASE_MESSAGING_SENDER_ID",
  appId: "YOUR_FIREBASE_APP_ID"
};
```

4. In the Firebase console, create a **Firestore** database and add a security rule to allow writes (start with test mode for development, then lock down for production).

Donation metadata is stored in the Firestore collection: **`donationSubmissions`**

> **Note:** Uploaded files are **not** sent to Firebase in this implementation. Only the filename is captured. Wire up Firebase Storage or a secured backend before accepting real files.

## 🔐 Production Security Checklist

This is a **client-side demonstration**. Before accepting real donations:

- [ ] Validate every submission again on the server
- [ ] Authenticate donors and administrators
- [ ] Apply Firebase Security Rules (least privilege)
- [ ] Validate uploaded files by MIME type, extension, size, and content
- [ ] Store uploads in Firebase Storage or a secure backend
- [ ] Scan uploaded documents for malicious content
- [ ] Never store raw card numbers or banking credentials
- [ ] Add server-side rate limiting and abuse protection
- [ ] Add an administrator-only audit queue
- [ ] Keep recipient approval data server-controlled
- [ ] Use HTTPS in production
- [ ] Use a PCI-compliant payment processor (e.g., Stripe) for real card donations

> The `PENDING_AUDIT_*` ticket generated by this demo is a temporary client-side submission identifier — **not** a blockchain transaction, payment confirmation, or legally binding charity receipt.
